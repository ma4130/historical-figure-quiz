# 著名人クイズ - リアルタイム投票クイズサイト

生徒がログイン不要でリアルタイムに回答できるクイズサイトです(kyudenクイズを元に作り直したもの)。
問題の形式は 単一選択・複数選択・記述・並び替え の4種類。

問題は **問題作成画面(`editor.html`)** で変えられる。管理者画面の「📝 問題を作成・編集する」から開く。

## 問題作成画面(editor.html)

- 問題の追加・削除・複製、↑↓で順番の入れ替え
- 種類(1つ選ぶ・全部選ぶ・文字で答える・並べ替え)、問題文、選択肢、正解、難易度、満点を変えられる
- 「保存する」で Firestore の `quiz/questions` に保存され、生徒・投影・管理者の全画面にすぐ反映される(GitHub に送り直す必要はない)
- まだ一度も保存していないときは `questions.js` の問題(偉人クイズ7問)を使う。「questions.js の問題に戻す」で元に戻せる
- 「questions.js として書き出す」で今の問題をファイルに保存できる(バックアップ用)
- 空の問題文・正解なしなどは保存前に止める。クイズの最中に開くと注意が出る(途中で変えると点数がずれるため)
- 管理者画面と同じく、このURLは生徒に教えないこと(誰でも問題を書き換えられてしまう)

## 点数と順位

- 正解した問題だけ点数が付き、早く答えるほど高い: `満点 × (1 − 0.5 × タイム ÷ 20秒)`(下限は満点の半分)
- 満点は難易度で決まる: かんたん 30 / ふつう 50 / むずかしい 100(`questions.js` の `difficulty`。`points` を書けばそちらを優先)
- 連続正解ボーナス: 2連続で満点の10%、3連続で20%…最大50%を上乗せ。「🔥3連続正解!」と表示
- 総合順位: 合計点の多い順。同点なら正解した問題のタイム合計が短い順(それも同じなら同順位)
- 計算は `scoring.js` の1か所にまとめてあり、生徒画面・投影画面・CSVで同じ結果になる
- 生徒のスマホには結果発表のとき「現在 7位(↑3)・1,240点」、画面下の行にも「・現在7位」を表示
  - 最後の問題の結果発表と、最終結果が公開されるまでは順位を出さない(ネタバレ防止)

## 最終結果の流れ

1. 管理者画面で「クイズを終了する」
2. 投影画面でドラムロール(約3.5秒)→ 優勝者とプレゼント画像を発表(ファンファーレ)
3. 約8秒後に、管理者画面が自動でスマホにも結果を公開(1位の人のスマホにはプレゼント画像)。
   「スマホに結果を公開する(今すぐ)」で早めることもできる。**管理者画面は閉じないこと**
   (閉じてしまったら、開き直してこのボタンを押す)

時間は `settings.js` で変えられる。

## プレゼント画像・効果音の差し替え

- プレゼント画像: 投影画面では最初は出さず、最終結果の一番下の「🎁 プレゼントの写真を見る」を押すと大きく出る(1位の人のスマホには最初から出る)。このフォルダの `prize.jpg` を置き換えるだけ(別の名前にするなら `settings.js` の `PRIZE_IMAGE`)。無いときは 🎁 を表示
- 効果音: 投影画面だけで鳴る。待機中の「🔊 音を有効にする」を押すまで鳴らない(右下で音量・ミュート)。
  ふだんはブラウザで合成した音。`sounds/` に `tick.mp3` などを置くとその音に差し替わる(`sounds/README.txt` 参照)

## 構成

- `index.html` + `app.js` … 生徒用画面(同じURLを開くだけで参加)。各自のスマホで開く
- `display.html` + `display.js` … 投影用(観客)画面。教室前方のスクリーン・プロジェクターに映す。
  登録・投票機能は持たず、Firestoreの状態を表示するだけの読み取り専用画面
- `host.html` + `host.js` … 先生(代表)用の進行管理画面。**このURLは生徒に共有しないこと。絶対に投影しないこと**
  (正解のプレビューが表示されるため)
- `questions.js` … 問題データ(問題作成画面で保存するまでの初期の問題)
- `questions-store.js` … 問題を Firestore から読む(全画面共通)
- `editor.html` + `editor.js` … 問題作成画面
- `scoring.js` … 点数・連続ボーナス・順位の計算(全画面共通)
- `settings.js` … プレゼント画像のファイル名、最終結果の待ち時間
- `sound.js` … 投影画面の効果音
- `effects.js` … カウントダウン、グラフのアニメーション、紙吹雪、プレゼント画像
- `firebase.js` … Firebase初期化共通処理
- `firebase-config.js` … あなたのFirebaseプロジェクトの設定値(要編集)
- `firestore.rules` … Firestoreセキュリティルール
- `style.css` … スマホ縦画面対応のレスポンシブデザイン

## セットアップ手順

### 1. Firebaseプロジェクトを作成

1. https://console.firebase.google.com/ で新しいプロジェクトを作成(無料のSparkプランでOK)
2. 「Firestore Database」を作成(本番環境モードでOK。ロケーションは `asia-northeast1` 等)
3. 「プロジェクトの設定」→「全般」→「マイアプリ」で ウェブアプリ を追加し、
   表示された `firebaseConfig` の値を `firebase-config.js` にコピーする

```js
window.FIREBASE_CONFIG = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "...",
};
```

### 2. Firestoreルールを設定

Firebaseコンソール → Firestore Database → ルール タブに `firestore.rules` の中身を貼り付けて公開する。

### 3. GitHub Pagesで公開

```bash
git init
git add .
git commit -m "著名人クイズサイトを追加"
git branch -M main
git remote add origin https://github.com/<あなたのアカウント>/<リポジトリ名>.git
git push -u origin main
```

GitHubリポジトリの Settings → Pages で、Source を `main` ブランチ / `/`(root) に設定して公開する。
数分後に `https://<あなたのアカウント>.github.io/<リポジトリ名>/` でアクセスできるようになる。

## 使い方(授業当日)

1. 先生は自分の端末で `.../host.html` を開いておく(**投影しない**)
2. 教室前方のスクリーンには `.../display.html` を投影する(こちらは正解が見えないので安心して映せる)
3. 先生が `.../host.html` で「新しいクイズを開始(リセット)」を押すと、`display.html` に参加用QRコードが表示される
4. 生徒はそのQRコード(または `.../index.html` のURL)を各自のスマホで開き、出席番号・名前を入力して待機する
5. 先生が「次の問題へ」を押し、確認で「OK」を押すと、`display.html` と生徒のスマホ両方の画面が自動で問題画面に切り替わる
   (`display.html` には問題文と回答数のみを表示し、選択肢や正解は出題中は表示されない)
6. 生徒が選択肢をタップ(複数選択・記述・並び替えは入力後にボタンで送信)すると同時に投票が記録される
   - 回答時刻は `serverTimestamp()` で記録するため、端末の時刻ズレの影響を受けない
7. 先生が「結果を見る」を押すと、`display.html` と生徒のスマホの両方に正解・投票分布の棒グラフ・
   正解者スピードランキング(上位10人)が表示される
8. 3〜8を最後の問題まで繰り返し、最後に「クイズを終了する」を押すと総合ランキングが両画面に表示される

## 設計メモ・注意点

- **ログイン不要**: Firebase Authenticationは使わず、Firestoreのルールで書き込みパターンを制限することで
  二重投票を防いでいます(同じ `questionIndex + 端末ID` の投票ドキュメントは1回しか作成できない)。
- **端末ID**: 初回アクセス時にランダムなIDを生成し `localStorage` に保存して使い回します。ブラウザのデータを消すと
  再投票が可能になってしまう点は、教室内利用という前提でのトレードオフです。
- **先生用ページの保護**: `host.html` には認証を設けていません。URLを生徒に教えないことで運用してください。
  Firestoreの `quiz/state` ドキュメントは誰でも書き込み可能な設定になっているため、より厳密にしたい場合は
  Firebase Authenticationの匿名認証+カスタムクレーム等の追加実装を検討してください。
- **複数選択問題(問3)**: 正解は「選択した組み合わせが完全一致」で判定しています。結果画面では選択肢ごとの得票率を表示します。
- **並び替え問題(問5)**: 各項目に順番(1〜5)をプルダウンで選んで回答する方式にしています。正解は完全一致判定です。
- **記述問題(問4)**: 前後の空白を除いた文字列の完全一致で正誤判定します。結果画面では回答の分布(上位8件)を表示します。
- **再実行**: 「新しいクイズを開始」を押すたびに新しい `sessionId` が発行されるため、同じ生徒が別の回でも投票し直せます
  (過去の投票データはFirestore上に残りますが、集計はセッションごとに独立しているので問題ありません)。
- **生徒データの削除**: `host.html` の「生徒データ管理」セクションで、出席番号・名前ごとに全セッション分の回答履歴をまとめて削除できます。
  この機能を有効にするため、Firestoreルールで `votes` コレクションの削除を全面許可(`allow delete: if true`)しています。
  認証機能がない構成のため、この削除権限は理論上 `host.html` 以外(URLを知っていれば)からも行使できてしまいます。
  `host.html` のURLを生徒に共有しないことで運用上守ってください。
